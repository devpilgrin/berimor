# ADR-0010: Присвоение класса модели — код по офлайн-оценке, не самооценка

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Допуск к исполнителям и бюджет контекста зависят от класса способностей модели (tier), но исходная спецификация Model Pool не описывала, кто и как этот класс присваивает — открытый вопрос, найденный при ревью архитектуры.

## Решение

Класс — поле реестра моделей. Стартовое значение задаётся вручную при регистрации (паспорт модели от провайдера). Дальше переопределяется офлайн-оценкой на золотом наборе: доля отказов валидации и доля успешных шагов CodeAct на контрольных задачах. Понижение класса — автоматическое событие при деградации метрик, применяется сразу. Повышение класса — только через подтверждение человека (I2).

## Альтернативы

- **Модель сама заявляет свой класс способностей** — отклонено: нарушает I1 (код решает допуск, не модель); заявленные провайдером возможности не обязаны совпадать с фактическим поведением на конкретных контрактах системы.

## Последствия

Требует поддерживать золотой набор и регулярно прогонять офлайн-оценку — эксплуатационная нагрузка. Асимметрия «понижение автоматом, повышение по подтверждению» защищает от тихого завышения допуска без ревью, ценой более медленного отклика на реальное улучшение модели.
