# Security Policy

Berimor — архитектура агентной системы, в которой безопасность (`arch/security-model.md`) не надстройка, а несущая конструкция (инварианты I4/I6, эшелоны L0–L8). Сообщения об уязвимостях в реализации разбираются с тем же приоритетом.

## Как сообщить об уязвимости

**Не открывайте публичный issue для уязвимости.** Используйте приватный канал:

- GitHub: вкладка **Security → Report a vulnerability** этого репозитория (Private Security Advisory) — предпочтительный способ.
- Если недоступно — откройте issue с пометкой `security` и минимумом деталей, попросив приватный канал связи; полное описание не публикуйте до координации.

Приложите: затронутый компонент (крейт/файл), класс проблемы (обход jail, утечка секрета, обход Mediation, инъекция и т.д.), минимальный воспроизводящий пример, потенциальное влияние.

## Что в периметре

- Обход слоёв `arch/security-model.md` §2 (deny-статика, jail, сетевой гейт, маскировщик, ACL плагинов).
- Утечка секрета через `berimor-secrets` в обход `Secret::reveal()` (например, через `Debug`/`Display`, сериализацию, паники).
- Обход Mediation: невалидный вывод модели, ставший состоянием без прохождения `parse → schema → policy → commit`.
- Побег из CodeAct-песочницы (`berimor-executors::codeact`, Wasmtime/WASM) за пределы объявленных host-функций.
- Обход верификации подписи в `deployment`/`bootstrap` (downgrade, подмена артефакта, подделка доверенного списка).

## Что вне периметра на текущей стадии

Проект — на стадии скелета (см. `README.md`, «Статус»): большинство модулей ещё не реализовано (см. `ROADMAP.md`). Отчёты вида «функция X не реализована» — не уязвимость, а открытая задача ROADMAP; заводите обычный issue.

## Ответ

Подтверждение получения — в разумный срок после сообщения. Публичное раскрытие — по согласованию после исправления, с указанием репортера (если не запрошена анонимность).
