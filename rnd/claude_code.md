# Claude Code: архитектура агента

> Источники: официальная документация Anthropic — https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/overview, статьи блога Anthropic и раздел "Building effective agents".

## Общее позиционирование

Claude Code — агентно-ориентированный интерфейс к моделям Claude, специализированный на программировании и работе с кодовой базой. Работает в терминале, веб-интерфейсе, десктопе, IDE (VS Code, JetBrains), Chrome-расширении и мобильном приложении. Использует встроенный набор инструментов для файловых операций, поиска, исполнения команд и веб-доступа, а также расширяется через навыки, MCP, хуки, субагентов и плагины.

## Отличительные черты

- **Проектный контекст через `CLAUDE.md`.** Постоянный файл проекта с правилами, соглашениями и референсами загружается в каждый сеанс.
- **Контекстное окно как первоклассный ресурс.** Агент явно управляет контекстом: автокомпакция, инструмент `/context`, изоляция субагентов, отложенная загрузка MCP-схем.
- **Слои разрешений.** Режимы Manual / Accept edits / Plan / Auto с фоновыми safety-checks в режиме Auto.
- **Контрольные точки (checkpoints).** Снапшоты файлов перед правками; откат через `Esc Esc` независимо от git.
- **Расширяемость через экосистему:** CLAUDE.md, Skills, Subagents, Agent teams, Code intelligence, MCP, Hooks, Artifacts, Plugins, Marketplaces.
- **Диалоговая модель взаимодействия.** Пользователь не пишет perfect prompt, а ведёт итеративную беседу с прерываниями и уточнениями.

## Ключевые файлы и папки

```
.claude/CLAUDE.md            # постоянные инструкции проекта (также CLAUDE.md в корне)
.claude/                     # директория агента: настройки, память, skills, MCP, hooks
~/.claude/                   # пользовательские настройки и skills
.claude/settings.json        # разрешения, разрешённые команды, scoped-настройки
```

## Как работает агент (core loop)

1. **Система читает CLAUDE.md** — постоянные инструкции проекта.
2. **Пользовательский запрос** добавляется в контекст.
3. **Claude рассуждает** и выбирает инструменты: чтение файлов, поиск, правка, терминал, веб, MCP, субагент.
4. **Выполняет инструменты** и получает результаты в контекст.
5. **Повторяет цикл**, пока задача не решена или не исчерпан бюджет.

Ключевой принцип: **Claude Code совмещает модель, рассуждающую о коде, с встроенными инструментами для файлов, поиска, исполнения и веба.**

## Встроенные инструменты

- Файловые операции (чтение, правка, создание, удаление).
- Поиск по кодовой базе (grep, file listing).
- Терминал (shell commands).
- Веб-доступ.
- Встроенные slash-команды: `/init`, `/doctor`, `/context`, `/compact`, `/mcp`, `/reset` и др.

## Контекстное окно

- В контексте держатся: история диалога, содержимое файлов, вывод команд, `CLAUDE.md`, авто-память, загруженные skills, системные инструкции.
- **Автокомпакция:** при приближении к лимиту Claude сначала удаляет старые выводы инструментов, затем суммарирует разговор. Ранние инструкции могут потеряться — поэтому их кладут в `CLAUDE.md`.
- **Управление контекстом:**
  - `/context` — показать, что занимает место.
  - `/compact focus on ...` — явно указать фокус компакции.
  - **Skills** — загружаются по требованию (описания видны сразу, полное содержимое — при использовании).
  - **Subagents** — изолированные субагенты со своим контекстом; возвращают только сводку.
  - **MCP** — имена инструментов загружаются сразу, полные схемы — по требованию через tool search.
- **Рекомендация:** держать `CLAUDE.md` < 200 строк, справочный материал выносить в skills.

## Режимы разрешений (permission modes)

| Режим | Поведение |
|-------|-----------|
| **Manual** | Спрашивает перед правкой файлов и shell-командами. |
| **Accept edits** | Правит файлы и выполняет обычные файловые команды (`mkdir`, `mv`) без запроса; остальные команды — спрашивает. |
| **Plan** | Исследует и предлагает план без изменения исходных файлов. |
| **Auto** | Оценивает действия фоновыми safety-checks и выполняет автоматически. |

Разрешённые команды можно явно внести в `.claude/settings.json` (например, `npm test`, `git status`). Настройки могут быть scoped от организационных политик до личных предпочтений.

## Контрольные точки (checkpoints)

- Перед правкой файла делается снапшот текущего содержимого.
- `Esc Esc` — откат к предыдущему состоянию.
- Контрольные точки независимы от git и сохраняются при возобновлении сессии.
- Не покрывают symlink/hardlink-файлы и удалённые действия над внешними системами (БД, API, деплои).

## Расширения и их layering

| Расширение | Что делает | Когда загружается | Контекстная стоимость |
|------------|------------|-------------------|------------------------|
| `CLAUDE.md` | Постоянный контекст проекта | Старт сессии | Полная цена каждый запрос |
| **Skills** | Повторяемые инструкции/рабочие процессы | Описания сразу, полное содержимое — при использовании | Низкая (только описания) |
| **Subagents** | Изолированные рабочие | При спавне | Изолированы от основной сессии |
| **Agent teams** | Координация нескольких независимых Claude Code-сессий | При спавне | Изолированы, обмен через сообщения |
| **Code intelligence** | Языковой сервер, навигация по символам, live diagnostics | После правок / по требованию | Низкая, уменьшает чтение файлов |
| **MCP** | Подключение внешних сервисов | Старт (имена), схемы — по требованию | Низкая до первого вызова инструмента |
| **Hooks** | Автоматизация по событиям | При срабатывании события | Ноль, если не возвращает контекст |
| **Artifacts** | Публикация вывода как интерактивная веб-страница | По требованию | Публикуется отдельно |
| **Plugins / Marketplaces** | Упаковка и распространение extensions | При установке | Зависит от состава |

### Приоритеты при конфликтах

- **CLAUDE.md** — аддитивны: все уровни (managed, user, project) загружаются одновременно; более специфичные инструкции обычно имеют приоритет.
- **Skills / Subagents** — override по имени: managed > user > project (skills); managed > CLI flag > project > user > plugin (subagents). Plugin-скиллы namespaced.
- **MCP servers** — override по имени: local > project > user.
- **Hooks** — merge: все зарегистрированные хуки срабатывают независимо от источника.

## Рекомендуемый порядок внедрения расширений

1. **CLAUDE.md** — соглашения и правила, которые Claude нарушает повторно.
2. **Skills** — регулярные процедуры (`/deploy`) и справочники (API patterns).
3. **MCP** — когда постоянно копируете данные из систем, которых Claude не видит.
4. **Code intelligence** — Claude тратит много времени на поиск символов.
5. **Subagents** — побочная задача заливает контекст выводами, которые больше не понадобятся.
6. **Hooks** — нужно автоматически запускать действие на каждое событие.
7. **Plugins** — одинаковая настройка нужна в нескольких репозиториях.

## Архитектурные паттерны (из "Building effective agents")

### 1. Augmented LLM

Базовая строительная единица: LLM + retrieval, tools, memory. Фундаментальные инструменты (поиск, правка, выполнение) решают большинство задач.

### 2. Workflows (предопределённые конвейеры)

- **Prompt chaining** — разбить задачу на последовательные LLM-вызовы, каждый с конкретной подзадачей.
- **Routing** — классифицировать вход и направить в специализированный downstream.
- **Parallelization** — LLM-ветви работают одновременно (например, review security, performance, style).
- **Orchestrator-workers** — центральный LLM динамически разбивает задачу, делегирует воркерам, агрегирует результаты.
- **Evaluator-optimizer** — цикл генерация → проверка → улучшение, пока качество не достигнет порога.

### 3. Autonomous agents

Агенты самостоятельно выбирают инструменты и действия в цикле, отражаясь на окружении. Работают лучше, когда:
- задачи требуют много шагов и заранее неизвестны;
- нужно масштабировать действия (выводы одного шага — входы следующего);
- процесс можно проверить и исправить.

Claude Code в режиме Auto — пример autonomous agent с фоновыми safety-checks.

## Code intelligence

Подключение к LSP (Language Server Protocol) для:
- перехода к определению символа;
- live type errors / diagnostics;
- уменьшения количества читаемых файлов.

Полезно в типизированных языках и больших кодовых базах.

## Практики эффективной работы

- **Будьте конкретны:** указывайте файлы, ограничения, примеры паттернов.
- **Дайте способ проверить:** тест-кейсы, скриншоты ожидаемого UI, формат вывода.
- **Сначала исследуйте, потом реализуйте:** режим Plan для анализа кодовой базы перед кодом.
- **Делегируйте, не диктуйте:** Claude сам разберётся, какие файлы читать и команды запускать.
- **Прерывайте и корректируйте:** `Esc` — остановить текущий шаг; отправьте уточнение без остановки, и Claude прочитает его после завершения текущего действия.
