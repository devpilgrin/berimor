# Memory Model — спецификация слоёв памяти

> Спецификация компонента. См. `ideal-agent-architecture.md` §3.6. Самодостаточна.

## 1. Слои

| Слой | Содержимое | Жизненный цикл | Кто пишет |
|------|------------|----------------|-----------|
| **Рабочая (STM)** | состояние процесса/сессии, промежуточные результаты шагов | жизнь задачи; сворачивается при переполнении | движок (патчи) |
| **Эпизодическая** | сессии, события шагов, решения, отчёты | журнал навсегда; уплотнение по политике | движок (события), никогда модель напрямую |
| **Семантическая** | факты, предпочтения, уроки («научи — вспомни») | консолидируется; устаревание по неиспользованию | только через валидацию и дедупликацию |
| **Процедурная** | навыки в виде документов | версионируется; контур здоровья навыков | только через подтверждение человека |

Модель хранения: журнал событий и документы в ключ-значение хранилище, полнотекстовый индекс для эпизодов, гибридный поиск (векторный + полнотекстовый с фиксированными весами) для семантики, файлы-документы для навыков.

## 2. Правила записи

Инвариант I1: модель не решает, что помнить.

```
кандидат на запись (факт/урок)
  → Mediation: контракт «предложение факта» {субъект, предикат, объект, уверенность, источник}
  → дедупликация: точное совпадение (хэш) → близкое (косинусная близость выше порога) → слияние/новый факт
  → commit в семантический слой + событие «факт записан»
```

- **Уверенность** — числовое поле факта; оценщик контекста использует её при сборке: факт с низкой уверенностью не попадает к слабой модели.
- **Защита от отравления памяти** (документированная угроза мультиагентных систем: вредоносный ввод через общую память): запись только через дедупликацию и контракт; источник факта обязателен; факты из непроверенных внешних каналов получают пометку «ненадёжный источник» и пониженный вес при выдаче.
- Противоречие нового факта существующему — не молчаливая перезапись, а конфликт-событие к человеку (инвариант I2).

## 3. Правила чтения

Модель не решает, что вспомнить.

- **Маршрутизатор** (код-правила): класс задачи → какие слои и какие запросы к памяти.
- **Выборка:** гибридный векторно-полнотекстовый поиск для семантики; полнотекстовый для эпизодов; навыки — по описаниям (всегда в доступе), полные тела — по требованию.
- **Сборщик:** фиксированный порядок слоёв контекста, бюджет по классу модели.
- В структурированных шагах у модели нет инструмента «сама поищи в памяти» — контекст собран заранее. В свободном режиме поиск по сессиям доступен как инструмент, но его выборки логируются.

## 4. Сжатие и консолидация

- **Сжатие рабочей памяти:** при приближении к бюджету история сворачивается суммаризацией (модель + контракт), оригинал остаётся в эпизодическом слое — потеря невозможна.
- **Консолидация семантики:** периодическое слияние фактов — дубликаты объединяются, противоречия уходят человеку конфликт-событием.
- **Граф сущностей (опциональный слой):** для доменов, где важны связи сущностей (инцидент → партия → поставщик → корректирующая мера), поверх семантического слоя строится граф: узлы — сущности, рёбра — типизированные отношения. Граф позволяет запрашивать прецеденты («все инциденты этого поставщика»), чего чистый векторный поиск не умеет. Включается профилем процесса, не глобально. Узлы и рёбра создаются только через контракты Mediation — детали ниже.

  - **Разрешение сущностей (entity resolution):** кандидат на новый узел сначала проверяется на совпадение с существующим — по точному идентификатору домена, если тип сущности его объявляет (например, номер партии), иначе по явной таблице псевдонимов (`alias_of` — типизированное ребро, тоже создаваемое через контракт, не эвристикой). Близкое совпадение по эмбеддингу — только предложение кандидата, не автослияние: ниже порога точного совпадения решение уходит человеку тем же конфликт-событием, что и при консолидации фактов (§4 выше). Автоматическое слияние без подтверждения — только при точном совпадении идентификатора.
  - **Согласованность типов:** каждый тип узла и тип ребра — контракт, версионируемый как схема данных (аналог `ClassificationOut` из `mediation.md`): объявляет обязательные поля, обязательность идентификатора для entity resolution и допустимые типы связей между парами типов узлов. Кандидат, не соответствующий ни одному объявленному типу или связывающий типы вне разрешённой пары, — отказ Mediation, а не свободнотипированная запись. Новый тип узла или связи — событие + подтверждение человека (I2), как любое расширение схемы навыков, не решение модели по ходу работы.
  - **Конфликтующие рёбра** (два источника утверждают взаимоисключающие связи для одной пары узлов) — конфликт-событие к человеку, не молчаливая перезапись последним по времени.

## 5. Изоляция и приватность

- **Профили:** память разделена по профилям/арендаторам; межпрофильное чтение — только явным правилом маршрутизатора.
- **Актор и профиль — одна ось изоляции, не две.** Рабочая и эпизодическая память актора (`ideal-agent-architecture.md` §3.8) — это профиль типа `actor`: те же правила маршрутизатора и то же «межпрофильное чтение только явным правилом» применяются к акторам, что и к профилям пользователей/арендаторов, без отдельного механизма. Семантический и процедурный слои по умолчанию общие на уровне арендатора, а не приватны актору — процесс может явно объявить актора отдельным профилем и в этих слоях, но это конфигурация, а не поведение по умолчанию.
- **Секреты не живут в памяти:** маскировщик стоит на записи в семантический и эпизодический слои (одна из точек маскировки, см. `security-model.md`).
- **Режим персональных данных:** опциональная маскировка персональных данных на записи — включение по желанию владельца профиля, не по умолчанию для всех.

## 6. Телеметрия

- Отказы записи (дубликат/политика) — индикатор качества извлечения фактов.
- Доля задач, где выбранный факт реально использован в ответе, — вход для оценки маршрутизатора.
- Число конфликтов консолидации — метрика зрелости базы фактов и размер очереди к человеку.

## 7. Границы

- Память не является источником истины для текущего шага — источник истины шага это состояние процесса.
- Модель не может записать в память в обход конвейера «контракт → дедупликация».
- Процедурный слой не меняется выполняющейся системой: навык меняется через событие и подтверждение, даже если свободный агент «нашёл способ лучше».
