# Бенчмарки berimor

Измерения по методологии `scripts/bench.sh` (воспроизводимо:
`scripts/bench.sh ~/.local/bin/berimor`). Машина: Linux 7.1.6-1-cachyos,
32 потока CPU, 126 ГБ RAM, NVMe. Версия: **0.20.0**. Дата: 2026-08-06.

## Числа (5 прогонов, честные — со всеми выбросами)

| Метрика | Значение |
|---|---|
| PSS интерактивной TUI-сессии (chat, простой) | **3.1–6.8 МБ** (RSS 9 МБ) |
| Холодный старт (`--version`, `--help`) | **~1 мс** |
| Time-to-first-render (TUI, pty) | **21 мс** (медиана; один выброс 6.8 с из пяти — фиксируем честно, причина не установлена, воспроизводится нестабильно) |

## Методология и оговорки

- **PSS** — `/proc/<pid>/smaps_rollup` живой TUI-сессии (pty через
  `script`, замер дочернего процесса через 3 с после запуска). Сессия в
  ПРОСТОЕ: модель ещё не вызывалась, wasmtime-хост CodeAct не
  инициализирован (компиляция гостя — при первом codeact-шаге, кэш
  OnceLock). Цифры первого отклика модели и активной работы — отдельной
  строкой, когда будет что честно измерить (см. ниже).
- **Холодный старт** — wall-clock `date +%s%N` вокруг вызова; страничный
  кэш тёплый после первого прогона (первый прогон серии тоже в таблице).
- **TTFI** — от exec до первого байта в pty-логе (опрос каждые 10 мс).

## Сравнение с опубликованными данными jcode (2026-08, их README)

| Метрика | jcode (без локальных эмбеддингов) | berimor 0.20.0 |
|---|---|---|
| PSS одной сессии | 27.8 МБ | **3.1–6.8 МБ** |
| Время до готовности ввода | 48.7 мс | **21 мс** (медиана) |

Оговорки, без которых сравнение нечестно: jcode измеряет на своей
методике и своей машине, их сессия включает активные подсистемы (память,
сервер); наша цифра — простой TUI до первого вызова модели. Прямое
сравнение возможно только на одной машине и одной методике — что этот
документ и обеспечивает для berimor. Общий вывод, который можно сделать
уже сейчас: архитектура «детерминированное ядро, никаких фоновых
подсистем по умолчанию» по ресурсам не уступает — и измерять это
регулярно есть теперь чем.

## План расширения

- PSS/TTFI под нагрузкой (после первого ответа модели, с wasmtime-хостом,
  с embedding-моделью — §20.23);
- стоимость дополнительной сессии (по методике «10 активных сессий»);
- CI: публикация чисел при релизе (не бюджет-тест — флаки недопустимы).
