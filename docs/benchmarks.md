# Бенчмарки berimor

Измерения по методологии `scripts/bench.sh` (воспроизводимо:
`scripts/bench.sh ~/.local/bin/berimor`). Машина: Linux 7.1.8-1-cachyos,
32 потока CPU, 126 ГБ RAM, NVMe. Версия: **0.48.0**. Дата: 2026-08-25.
Предыдущая серия — 0.20.0 (2026-08-06), числа сохранены ниже для
динамики.

## Числа 0.48.0 (5 прогонов, честные — со всеми выбросами)

| Метрика | Значение |
|---|---|
| PSS интерактивной TUI-сессии (chat, простой) | **25.7–25.8 МБ** (RSS 76 МБ) |
| Холодный старт (`--version`, `--help`) | **23–26 мс** |
| Time-to-first-render (pty.fork) | **23 мс** |
| TTFI через `script -qec` (методика 0.20.0) | 4.5 с, стабильно — **артефакт обвязки `script`**, не приложения: прямой pty.fork той же сессии даёт 23 мс. Серия 0.20.0 с тем же артефактом давала 21 мс — обвязка деградировала сама (версия util-linux), беречься сравнения |
| PSS после попытки обмена с моделью | **25.8 МБ** (см. оговорку про round-trip) |
| Стоимость сессии (10 параллельных TUI в простое) | **20.2 МБ PSS на сессию, 202 МБ суммарно** (общие страницы уже вычтены — PSS) |

## Динамика 0.20.0 → 0.48.0 (28 релизов)

| Метрика | 0.20.0 | 0.48.0 | Что случилось |
|---|---|---|---|
| PSS простоя | 3.1–6.8 МБ | 25.8 МБ | Рост ~4-8×: память (факты/эмбеддинги-шов), каталоги скиллов/агентов/плагинов, MCP-клиент, metering, OAuth. Регрессия зафиксирована честно; разбор по подсистемам — отдельной задачей, здесь не расследуется |
| Холодный старт | ~1 мс | ~24 мс | Рост: загрузка конфига, каталогов, планировщика. Всё ещё на порядки ниже человеческого порога |
| TTFI (честный pty) | ~21 мс | ~23 мс | Без регрессии |

## Методология и оговорки

- **PSS** — `/proc/<pid>/smaps_rollup` живой TUI-сессии. Простой: модель
  не вызывалась, wasmtime-хост CodeAct и embedding-модель не
  инициализированы (обе — лениво, по первому использованию).
- **Под нагрузкой**: PSS после одной попытки обмена с моделью —
  25.8 МБ (дельта против простоя в пределах шума). Сам round-trip
  модели этим харнессом не зафиксирован (TUI-pty парсинг ленты
  нестабилен) — метрика «время до первого байта ответа модели»
  остаётся открытой, измерять надёжнее через journal/OTLP-трейс
  (события usage несут латентность с 0.39.0).
- **Стоимость сессии** — 10 параллельных `chat` в pty в простое; PSS
  учитывает разделяемые страницы (строка/данные бинарника), поэтому
  честная маргинальная цена сессии — 20.2 МБ.
- **TTFI**: две цифры специально обе — урок методологии: обвязка
  измерения может врать на порядки и дрейфовать между версиями ОС.

## Сравнение с опубликованными данными jcode (2026-08, их README)

| Метрика | jcode (без локальных эмбеддингов) | berimor 0.48.0 |
|---|---|---|
| PSS одной сессии | 27.8 МБ | 25.8 МБ (простой) / 20.2 МБ (маргинальная) |
| Время до готовности ввода | 48.7 мс | 23 мс (pty.fork) |

Оговорки прежние: их методика и машина — не наши; наша сессия — простой
до первого вызова модели. Прямое сравнение возможно только на одной
машине и одной методике.
