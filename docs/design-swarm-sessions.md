# Дизайн §20.22 v2: межсессионные уведомления (swarm на общем журнале)

**Статус:** проект (2026-08-06). v1 (schedule + daemon) закрыт в 0.20.0.

## Контекст

jcode swarm: несколько агентов в одном репозитории, сервер уведомляет
«агент A переписал файл, который читал агент B», агенты пишут друг другу
(DM/broadcast), координатор порождает воркеров. У berimor уже есть
персистентный транспорт: почтовые конверты в общем SQLite-журнале
(`MailboxLog`: persist_envelope/undelivered_for, идемпотентная постановка —
аудит 4.8) и ACL топиков на шине. Не хватает: (1) регистрации живых
сессий, (2) событий об изменениях файлов, (3) доставки в REPL/TUI.

## Решение (по возрастанию объёма)

### Шаг 1. Реестр сессий + heartbeat (основа всего)

- Сессия (`berimor` chat/run/daemon) при старте пишет в журнал событие
  `SessionOpened {session_id, cwd, pid}` и каждые N секунд —
  `SessionHeartbeat`; при выходе — `SessionClosed` (best-effort;
  отсутствие heartbeat > 3N = мертва, считается кодом при чтении, не
  сторожком).
- «Живые сессии хоста» = запрос по журналу (последние heartbeat). Новая
  команда `berimor sessions` — список.

### Шаг 2. Уведомления о файлах (ядро swarm-ценности)

- Записной путь инструментов (files.write/patch/terminal.exec в chat и в
  tool-шагах процессов) журналирует `FileTouched {session_id, path, op}`
  — точка одна: обёртка в builtin-диспетчере, не рассылка по
  инструментам.
- Читной путь (files.read) журналирует `FileObserved {session_id, path}`
  (потолок: уникальные пути за сессию, не каждый вызов — журнал не
  раздувается).
- При записи `FileTouched`: код ищет в журнале живые сессии с
  `FileObserved` того же пути и кладёт им конверт топика
  `file.changed` {path, by_session} — mailbox уже персистентен, офлайн-
  сессия прочтёт при возвращении.
- Доставка в чат: цикл чата раз в ход проверяет `undelivered_for` своего
  session-актора и показывает строку «⚠ <path> изменён сессией
  <id> (diff доступен)». Никаких фоновых потоков в v2 — проверка на
  границе хода (детерминированно, тестируемо).

### Шаг 3. Сообщения между сессиями

- `/tell <session> <текст>` и `/broadcast <текст>` в чате → конверты
  топика `session.message`; доставка — тот же опрос на границе хода.
- ACL топиков шины (уже реализован в bus.rs) — по манифесту
  сессионного «актора», не свободная запись.

### НЕ в v2 (отложено обоснованно)

- Фоновые потоки/пуш в TUI (прерывание рендера) — опрос на границе хода
  покрывает ценность без рисков гонок отображения.
- Авторазрешение конфликтов (jcode: «агент B сам смотрит diff») — v3,
  требует решения о доверии авточтению diff моделью.
- Координатор→воркеры через swarm-инструмент — покрыто субагентами
  (`agents.run` + allow_spawn), отдельного транспорта не требует.

## Тесты

- Юнит (in-memory journal): реестр (open/heartbeat/dead-порог),
  FileTouched → конверт наблюдателю, идемпотентность при повторной
  записи (4.8), отсутствие конверта мёртвой сессии.
- e2e (бинарник): две сессии chat на общем XDG (два REPL-процесса):
  A читает файл, B пишет файл, A на следующем ходу видит строку
  уведомления; `/tell` от B к A доходит; `berimor sessions` показывает
  обе.
- Потолок FileObserved: N+1 чтений одного пути — одна запись.
