# Провайдеры решений: Jev и Kev

`branch` у berimor маршрутизирует кодом, но по значению, которое предложила модель,
и контракт проверяет форму этого значения, не смысл (см. «Честная граница подхода» в
README). Провайдеры решений закрывают эту дыру для маршрутов. Модель класса «System One»
не генерирует текст: на типизированный вопрос она отвечает калиброванной вероятностью.
Код получает и само значение, и меру уверенности в нём.

Поддерживаются два провайдера. Оба говорят одним протоколом `POST /v1/systemone`, поэтому
в berimor у них один клиент:

| Провайдер | Где работает | Модель | Ключ |
|---|---|---|---|
| **Jev** (TypeSafe AI) | облако, `https://api.typesafe.ai` | `jev-latest` | `TYPESAFE_API_KEY` |
| **Kev** (Jared Palmer, Apache-2.0) | локально, `kev.serve` | `kev-latest` | не нужен (или `KEV_API_KEY`) |

Секция опциональна целиком. Без неё berimor работает как раньше.

## Настройка

```toml
# Локальный Kev: kev.serve на этой же машине
[[decision_providers]]
name = "kev"
base_url = "http://127.0.0.1:8009"
model = "kev-latest"
allow_private_endpoint = true   # opt-in на локальный адрес, как у [[providers]]

# Облачный Jev
[[decision_providers]]
name = "jev"
base_url = "https://api.typesafe.ai"
model = "jev-latest"
api_key_env = "TYPESAFE_API_KEY"
# request_timeout_secs = 30     # по умолчанию 30 с (Kev-4B на CPU — ~2 с на вопрос)
```

Порядок секций задаёт порядок отката: без явного `provider` вызов идёт к первому, при
сбое — к следующему. Слои конфигурации сливаются по `name`, как `[[providers]]`:
проектный слой перекрывает глобальный.

Kev запускается отдельно: `uv run --extra serve python -m kev.serve --run jaredpalmer/kev-4b --port 8009`
в клоне [jaredpalmer/kev](https://github.com/jaredpalmer/kev). `/models` в чате
показывает настроенных провайдеров решений.

## Инструмент `decision.ask`

```yaml
- id: decide
  type: tool
  tool: decision.ask
  args:
    state: "{{state.ticket.text}}"       # документ/контекст
    min_confidence: 0.6                  # ниже — routed = "uncertain"
    on_failure: uncertain                # error (по умолчанию) | uncertain
    # provider: kev                      # явный провайдер, без отката
    questions:
      team:
        type: choice                     # noul | choice | score
        instructions: "Какой команде передать обращение?"
        criteria:
          billing: "оплата, списания, счета"
          shipping: "доставка"
          technical: "ошибки приложения"
```

Требования к вопросам: у `choice` в `criteria` не меньше двух вариантов (ключ → описание),
у `score` — не меньше двух уровней шкалы (массив), у `noul` `criteria` необязательны.
`instructions` непусты всегда. Ошибки в аргументах отклоняются до обращения к сети.

Ответ:

```json
{
  "provider": "kev",
  "model": "kev-latest",
  "answers": {
    "team": {"type": "choice", "choice": "billing", "confidence": 0.93,
             "probabilities": {"billing": 0.954, "shipping": 0.01, "technical": 0.036},
             "routed": "billing"}
  },
  "latency_ms": 1526.4,
  "skipped": [],
  "degraded": false
}
```

Исходные поля провайдера сохраняются как есть. Инструмент добавляет к ним два поля:

- `confidence` — у `choice`/`score` это значение провайдера, у `noul` это `max(p, 1 − p)`;
- `routed` — строка для `branch`: у `noul` это `yes`/`no`, у `choice` — ключ варианта,
  у `score` — метка самого вероятного уровня из `legend`. Если `confidence < min_confidence`,
  здесь будет `uncertain`.

Маршрутизация — обычный `branch`:

```yaml
- id: route
  type: branch
  on: state.decide.answers.team.routed
  cases:
    billing: assign
    shipping: assign
    technical: assign
    uncertain: manual_triage       # к человеку
```

Для числовых условий доступны сами вероятности, например
`on: state.decide.answers.spam.noul` с `cases: {">=0.9": block, "<0.9": pass}`.
Полный пример: [`fixtures/golden/processes/decision-routing.yaml`](../fixtures/golden/processes/decision-routing.yaml).

В свободном цикле (`agent_step`, чат) инструмент объявляется модели только при
настроенных провайдерах.

## Работа без провайдеров

Опциональность устроена на трёх уровнях:

1. **Секции нет.** Модели инструмент не объявляется. Вызов из процесса отвечает ошибкой
   с подсказкой, как включить провайдеры, либо деградирует (см. п. 3).
2. **Нет ключа.** Если `api_key_env` задан, а переменная пуста, провайдер при старте
   помечается недоступным и печатается предупреждение. Запуск **не** падает, вызовы идут
   к следующему провайдеру.
3. **`on_failure: uncertain`.** Если ответить некому (секции нет или все провайдеры
   недоступны), все ответы получают `routed = "uncertain"`, а результат — `degraded: true`.
   Процесс уходит в ветку для человека, а не падает. Поэтому один и тот же процесс
   работает и с Jev/Kev, и без них: с провайдером решение принимается автоматически,
   без него — человеком.

## Откат между провайдерами

К следующему провайдеру вызов переходит при сбое самого провайдера: сетевая ошибка,
таймаут, отказ сетевого гейта, HTTP 401/403/404/408/429/5xx, ответ не по протоколу.
При ответе 400/413/422 отката нет: это ошибка самого запроса, и другой провайдер её
не исправит. Такая ошибка возвращается как есть даже при `on_failure: uncertain`, чтобы
не прятать баг в процессе. Кто и почему не ответил, видно в `skipped` — это пишется
в журнал.

## Безопасность

- **Адрес задаёт владелец в конфиге, а не модель.** Он проходит сетевой гейт
  (`net_gate::check_endpoint`, тот же разбор, что у `[[providers]]`). Приватный адрес
  разрешается только с `allow_private_endpoint = true`. Редиректы не следуются.
- **Ключ Jev регистрируется в маскировщике**, поэтому в журнал и вывод он не попадает.
  В ошибках заголовки запроса не показываются.
- **`mutates: false`**: инструмент ничего не меняет. Но при провайдере Jev `state`
  уходит в облако TypeSafe. Это то же доверие, что к облачным `[[providers]]`: не
  подключайте Jev к процессам с данными, которые не должны покидать периметр, — для
  них есть локальный Kev.
- **Кап размера**: `state` — до 256 КиБ, вопросов — до 64, ответ провайдера — до 1 МиБ.

## Ограничения

- **Jev вживую не проверялся** (нет ключа TypeSafe). Протокол взят из официального SDK
  `typesafe-sdk` 0.6.0 (адрес, путь, заголовок `Authorization: Bearer`) и покрыт
  тестами на моке. Kev проверен вживую: и уверенный маршрут, и уход к человеку при
  `confidence < min_confidence`.
- `confidence` у `choice`/`score` — формула конкретного провайдера, а не вероятность
  лучшего варианта. Порог `min_confidence` стоит подбирать на своих данных.
- Kev на CPU отвечает за 0.4–2 с на вопрос (0.8B/4B). Для горячего цикла `agent_step`
  это дорого, а для шага процесса нормально.
- Kev учили в основном на английском. На русском он работает, но уверенность ниже.
