# Ответ на полевой отчёт по 0.27.0 (14.08.2026) — что сделано в 0.28.0

Спасибо за отчёт — это лучшее внешнее тестирование, которое проект
получал: воспроизводимые дефекты с контрольными опытами и локализацией
до строки. Все семь пунктов обработаны в день получения; основная ветка
— `devpilgrin/berimor`, релиз v0.28.0.

## Блокирующие

**BR-01 (промпт свободного цикла без имён инструментов)** — промпт хода
теперь перечисляет доступные имена с сигнатурами аргументов, по образцу
промпта исполнения кода. Перечень фильтруется потолком скилла/субагента.
Попутно обнаружилась протухшая витрина `tools_catalog` (застыла на
исходных пяти инструментах) — дописаны все 13.

**BR-02 (markdown-ограждение в codeact)** — ограждение снимается до
статического анализа и до передачи в песочницу; промпт явно просит
чистый текст программы. Контрольный опыт с эталонной программой в
ограждении теперь проходит как unit-тест.

## Значимые

**BR-03 (журнал слеп к ходам агента)** — новые события:
`AgentToolTurn` (инструмент, маскированные аргументы и наблюдение,
решение) и `CodeActProgramRejected` (стадия, причина, маскированный
текст программы). `berimor trace` их рендерит; критерий приёмки
«диагностика без внешнего прокси» выполнен.

**BR-04 (посторонние прогоны в контексте)** — слой Session выключен по
умолчанию: `[memory] session_context = true` включает осознанно. Это
изменение поведения по умолчанию — принято, т.к. неявная передача
сведений за границу задачи недопустима для части контуров.

**BR-05 (зависание неинтерактивного запуска)** — `berimor run
--non-interactive` (или `BERIMOR_NON_INTERACTIVE=1`): подтверждение =
немедленный отказ с диагностикой и указанием путей (интерактивный
запуск / точечное автоподтверждение в `.berimor/allow`). Демон и
HTTP-сервис неинтерактивны по определению. Раздел автоматизации в
README упоминает автоподтверждение.

## Незначительные

**BR-06 (тильда)** — `~/` раскрывается в `$HOME` до лексической
проверки границы; `~user` и `$VAR` остаются консервативно «вне».

**BR-07 (версия в инструкциях)** — во всех 8 README версия подставляется
автоматически (GitHub API, последний выпуск) — и в sh, и в PowerShell.

## Архитектурное

**Контракты из конфигурации** — реализовано: секция `[[contracts]]` с
JSON Schema (inline или `schema_path`), `llm_structured` и `codeact`
принимают их наравне с кодовыми; generic-медиация (разбор → валидация
по схеме → контроль утечек → патч), ошибка валидации уходит в промпт
повтора. Осознанные ограничения (задокументированы): нет policy-правил
и версий схем, `publishable` — весь объект, реестр читается при
старте. Пример — `fixtures/golden/processes/config-contracts/`.
Проверено живым прогоном сценария «протокол встречи» — задача из вашей
методики решается конфиг-контрактом без пересборки.

**Замечание о позиционировании** — принято и опубликовано: в README
добавлен абзац «Честная граница подхода» (контракт проверяет форму,
не смысл; маршрут вычисляется по предложенному моделью значению) и
граница слабых моделей в свободном цикле. Это честнее, чем «проблема
доверия решена», — спасибо за формулировку «перенесена на уровень
вниз», она точная.

**Дополнение (0.29.0, та же волна):** граница слабых моделей в
свободном цикле смягчена. Три формы сбоев из вашего протокола
(`unknown field 'reply'`, `invalid type: string "tool"`, оборванный
JSON) теперь достраиваются детерминированным нормализатором ДО
медиации — смысл по-прежнему решают валидация и гейт, ремонт
журналируется событием `agent_turn_normalized`. Промпт хода получил
few-shot примеры. Заодно закрыт интеграционный пробел: `agent_step`
принимает конфиг-контракты для финального результата (в 0.28.0 —
только `llm_structured`/`codeact`). Ваш воспроизводитель BR-01
(«прочитай meetings/ и выпиши поручения») теперь решается свободным
циклом с конфиг-контрактом — проверено живым прогоном.

чист), два релиза: v0.28.0 (дефекты + конфиг-контракты) и v0.29.0
(нормализатор + agent_step с конфиг-контрактами). Отдельное спасибо
за качество приложений — mock_wrapped.py как доказательство BR-02 это
образцовая изоляция дефекта.
