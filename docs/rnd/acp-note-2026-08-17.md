# ACP (Agent Client Protocol) — проектная заметка для berimor

2026-08-17. По мотивам deepseek-ai/deepseek-harness (packages/acp).

## Что это
ACP — JSON-RPC протокол (stdio) между редактором (Zed и др.) и агентом:
редактор — клиент, агент — сервер. Позволяет выбрать berimor как
агентный бэкенд редактора: промпт из IDE, стриминг ответа, tool-calls
с подтверждениями в UI редактора.

## Почему отдельная волна, а не пункт
Полный сервер: initialize/Authenticate, session/new, session/prompt
(streaming session/update), session/cancel, fs/terminal capabilities
редактора (делегирование чтения/записи клиенту), permission-запросы.
Это ~новая подсистема CLI (`berimor acp`), маппинг нашего
capability-гейта на permission-модель протокола и тестовый клиент.
Оценка: 2-3 дня с приёмкой в живом Zed.

## Границы решения (когда возьмёмся)
- Транспорт: stdio JSON-RPC (NDJSON), без websockets.
- Подмножество: initialize, session/new, session/prompt, session/cancel;
  fs/* и terminal/* редактора — v2 (наши файловые инструменты уже
  ограничены jail, делегирование редактору — отдельная модель доверия).
- Подтверждения: наш human_gate/confirmation → session/request_permission.
- Журнал: каждый ACP-сеанс — обычная сессия berimor (SQLite), trace
  доступен из редактора ссылкой.
- Провайдеры и модели — из конфига berimor; выбор модели в редакторе
  маппим на `model_tier`, не на прямой выбор (философия пула).

## Предпосылки (уже готовы)
- Неинтерактивный режим (BR-05) и стриминг событий в stdout.
- Capability-гейт с confirm-колбэком — прямая точка для permission.
- Имена инструментов стабильны (builtin.rs) — маппинг на ACP tool-kinds.

## Референсы
- dsh packages/acp/acp — серверная сторона на TS.
- agentclientprotocol.com — спецификация протокола.
