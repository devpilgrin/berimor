# Задача: доработка проекта berimor (Rust workspace)

Ты — инженер-исполнитель в проекте **berimor** (`/home/roman/workspace/berimor`, GitHub: devpilgrin/berimor). Это детерминированное ядро агентной системы для LLM: Rust workspace, крейты под `crates/`. Актуальные версия и счётчик тестов — из `Cargo.toml` и прогона `cargo test --workspace`, не из документов.

## Архитектурные принципы (нарушение = брак)

1. **Решения принимает детерминированный код, модель — только исполнитель рутины.** Слабым моделям нельзя доверять отбор контекста и маршрутизацию.
2. **Golden-фикстура раньше кода** (`fixtures/golden/`).
3. **Никаких новых внешних зависимостей** без крайней необходимости; тяжёлые — только за cargo feature-флагом, выключенным по умолчанию.
4. Комментарии, документация, тексты ошибок — **на русском**.
5. TLS — только rustls (не OpenSSL). Сети в тестах нет — моки на `127.0.0.1` через `std::net::TcpListener`.
6. **Ничего не заявлять «готово» без прогона.** «Написан код» ≠ «работает».

## Тулчейн (критично)

- Cargo — **только `~/.cargo/bin/cargo`** (rustup-стабильный, с wasm32-wasip1). Системный `/usr/bin/cargo` НЕ использовать.
- Перед любым «готово» — **тройка целиком**:
  ```
  ~/.cargo/bin/cargo fmt --all -- --check
  ~/.cargo/bin/cargo clippy --workspace --all-targets -- -D warnings
  ~/.cargo/bin/cargo test --workspace
  ```
- Счётчик тестов в README ×8 обновляется CI-шагом (см. `.github/workflows`) — не правь число вручную.
- Коммиты: сообщение с ID задачи, от имени владельца репозитория, БЕЗ Co-Authored-By. Коммит и пуш — только когда пользователь явно разрешил в текущей сессии.

## Подводные камни (проверено кровью)

- **`patch`-инструменты с fuzzy-матчем** могут приземлиться не туда или съесть закрывающие скобки/соседние декларации — после КАЖДОЙ порции правок: `cargo check --workspace --all-targets` немедленно, плюс grep точек приземления.
- **Инструмент чтения файлов может маскировать `Option<String>` как `***`** (авто-редакция) — якорь для patch сверяй grep'ом, никогда не копируй `***` в new_string.
- **Тест-каталоги в /tmp от `std::process::id()`** общие для всех тестов процесса — добавляй уникальный тег/счётчик в имя.
- **Каждый e2e-харнесс, спавнящий бинарник, обязан изолировать `XDG_CONFIG_HOME` и `XDG_DATA_HOME`** — иначе реальный конфиг машины разработчика подмешается в тесты.
- Бинарник для ручных прогонов пересобирай явно: `cargo test` НЕ обновляет `target/debug/berimor`.
- `berimor-cli` — bin-only крейт: юнит-тесты через `cargo test -p berimor-cli --bin berimor`.
- Новый вариант `EventKind` = обязательная правка `berimor-eval/src/trace.rs` (exhaustive match — компилятор напомнит).
- fastembed НЕ добавляет префикс `passage:` сам — в `embed()` он уже учтён, не удаляй.

## Приёмка

По каждой задаче отдельно: код + тесты + реальный прогон (не только юниты) + тройка зелёная + краткий отчёт «что доказано прогоном / что нет». Задачи делай по одной. Релиз — `scripts/release.sh <ver>` после явного разрешения; npm install для проверки установленного бинарника — обязателен.
