# Задача: доработка проекта berimor (Rust workspace)

Ты — инженер-исполнитель в проекте **berimor** (`/home/roman/workspace/berimor`, GitHub: devpilgrin/berimor). Это детерминированное ядро агентной системы для LLM: Rust workspace, 13 крейтов под `crates/`. Текущая версия — 0.24.0, 778 тестов зелёных.

## Архитектурные принципы (нарушение = брак)

1. **Решения принимает детерминированный код, модель — только исполнитель рутины.** Слабым моделям нельзя доверять отбор контекста и маршрутизацию.
2. **Golden-фикстура раньше кода** (`fixtures/golden/`).
3. **Никаких новых внешних зависимостей** без крайней необходимости; тяжёлые — только за cargo feature-флагом, выключенным по умолчанию.
4. Комментарии, документация, тексты ошибок — **на русском**.
5. TLS — только rustls (не OpenSSL). Сети в тестах нет — моки на `127.0.0.1` через `std::net::TcpListener`.
6. **Ничего не заявлять «готово» без прогона.** «Написан код» ≠ «работает».

## Тулчейн (критично)

- Cargo — **только `~/.cargo/bin/cargo`** (rustup-стабильный, с wasm32-wasip1). Системный `/usr/bin/cargo` НЕ использовать.
- Перед любым «готово» — **тройка целиком**:
  ```
  ~/.cargo/bin/cargo fmt --all -- --check
  ~/.cargo/bin/cargo clippy --workspace --all-targets -- -D warnings
  ~/.cargo/bin/cargo test --workspace
  ```
- Подсчёт тестов: `... | grep -oE '[0-9]+ passed' | grep -oE '^[0-9]+' | awk '{s+=$1} END {print s}'` — должен быть ≥778 и расти.
- Коммиты: сообщение с ID задачи, от имени владельца репозитория, БЕЗ Co-Authored-By. Коммит и пуш — только когда пользователь явно разрешил в текущей сессии.

## Контекст кодовой базы (что уже есть)

- `berimor-storage`: журнал событий SQLite, семантическое хранилище фактов, `SemanticStore::hybrid_search` (гибридный поиск: FTS5 + косинусная близость эмбеддингов через sqlite-vec) — **написан, но не вызывается нигде за пределами storage**.
- `berimor-memory`: факты/дедупликация; `embeddings.rs` — feature `embeddings`, fastembed 5.17.4 + BGE-M3 (1024 dim), `FastEmbedder::embed(&str) -> Result<Vec<f32>, String>`, ленивая загрузка ~2 ГБ при первом вызове, калиброванный порог слияния 0.75 (`MERGE_THRESHOLD_EMBEDDINGS`).
- `berimor-context-engine`: `MemoryContextBuilder` (слои контекста, бюджеты); слой `Facts` упоминает `hybrid_search` в комментарии, но не вызывает его.
- `berimor-cli`: `run.rs` (прогон процессов), `chat.rs` (REPL), `chat_tui.rs` (TUI), `daemon.rs` (планировщик расписаний, `berimor daemon`), `sessions.rs` (реестр живых сессий, почтовые конверты между сессиями), `oauth.rs` (PKCE-логины).
- Конфиг: `~/.config/berimor/config.toml` + локальный `./berimor.toml`; `[memory] embeddings = true` уже поддержан (opt-in).
- `docs/ROADMAP.md` — источник истины по задачам; `docs/ADR/` — принятые решения. `.remember/remember.md` — handoff прошлых сессий.

## Задачи (в порядке приоритета)

### Задача 1 (ГЛАВНАЯ): семантический поиск фактов в контекст чата

Сегодня эмбеддинги работают только на дедупликацию при записи. Подключить чтение:

1. В `MemoryContextBuilder` слой `Facts` должен вызывать `SemanticStore::hybrid_search` с эмбеддингом текущего сообщения пользователя: релевантные факты подтягиваются в контекст хода (с учётом бюджета слоя — см. `apply_budget`).
2. Эмбеддер — через существующий шов: когда `[memory] embeddings = true` И собрано с `--features embeddings`, используется `FastEmbedder`; иначе — прежнее поведение (слой деградирует без эмбеддингов, как сейчас — деградация обязана быть безопасной и тихой).
3. Ошибки эмбеддера/хранилища — не «пустой результат молча»: видимое предупреждение в stderr, ход продолжается без фактов (принцип: сбой памяти не хоронит ход).
4. Тесты: юнит с мок-эмбеддером (фиксированные векторы) — факты ранжируются по близости к запросу, нерелевантные отсекаются порогом; слой уважает бюджет; без фичи embeddings поведение прежнее. Один `#[ignore]`d тест с реальной моделью (скачивает ~2 ГБ, запуск `--include-ignored` локально).
5. E2E: записать факт через одну сессию, в другой задать перифразированный вопрос (RU↔RU и RU↔EN) — факт появляется в контексте (проверка записывающим мок-провайдером по сырому телу запроса).

### Задача 2: `berimor serve` — сервисный режим

HTTP-сервер (в существующем tokio-стеке, без новых тяжёлых фреймворков — или обоснуй выбор): эндпоинты запуска процесса по имени файла, статус расписаний (чтение `ScheduleStore`), список живых сессий (чтение реестра). Аутентификация — токен из конфига (не анонимный доступ к исполнению процессов!). Порт — конфигурация, дефолт loopback-only. Тесты: мок-запросы к локальному экземпляру.

### Задача 3: консолидация памяти

`berimor memory consolidate` (или фоновая задача демона): слияние семантических дублей фактов (порог 0.75), отчёт о слияниях, ничего не удаляется молча — журналируется. Тесты на in-memory storage.

### Задача 4: компакция длинных сессий чата

При переполнении бюджета контекста — суммаризация старой части ленты диалога (вызовом модели) вместо молчаливого сброса слоёв. Маркер в ленте («предыстория сжата»). Тесты с мок-провайдером.

### Задача 5 (по остаточному принципу): контент каталогов

Репозитории devpilgrin/berimor-skills и devpilgrin/berimor-agents: 3–5 боевых скиллов и 1–2 субагентов по форматам из `docs/` (форматы заморожены, обратная совместимость обязательна).

## Подводные камни (проверено кровью)

- **`patch`-инструменты с fuzzy-матчем** могут приземлиться не туда или съесть закрывающие скобки — после КАЖДОЙ порции правок: `cargo check --workspace --all-targets` немедленно, плюс grep точек приземления.
- **Тест-каталоги в /tmp от `std::process::id()`** общие для всех тестов процесса — добавляй уникальный тег/счётчик в имя.
- **Каждый e2e-харнесс, спавнящий бинарник, обязан изолировать `XDG_CONFIG_HOME` и `XDG_DATA_HOME`** — иначе реальный конфиг машины разработчика подмешается в тесты.
- Бинарник для ручных прогонов пересобирай явно: `cargo test` НЕ обновляет `target/debug/berimor`.
- `berimor-cli` — bin-only крейт: юнит-тесты через `cargo test -p berimor-cli --bin berimor`.
- Новый вариант `EventKind` = обязательная правка `berimor-eval/src/trace.rs` (exhaustive match — компилятор напомнит).
- fastembed НЕ добавляет префикс `passage:` сам — в `embed()` он уже учтён, не удаляй.
