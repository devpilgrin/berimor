# ADR-0028. Отказные решения волны L: рой/A2A, WASM-снапшоты, спекулятивные ветки, similarity-кэш

Статус: принято (2026-08-24). Контекст: ROADMAP §21.1, волна L
(исследовательская). Формат: доказательство отказа + условия пересмотра.
Доказательства опираются на инварианты I1 (маршрутизация — только код),
I2 (изменения — событие + подтверждение), event-sourced журнал как
источник истины и единственный способ восстановления (resume/replay).

## L1. Распределённый рой / A2A — отклонено

**Тезис.** Рой ломает единственное, что делает систему berimor — и ломает
не интерфейсно, а в основании.

**Доказательство.** Журнал детерминирован ровно потому, что у прогона один
писатель и один порядок событий на одной машине: replay и resume
восстанавливают состояние, потому что последовательность событий
тотальна и однозначна. Рой вводит сеть: частичные отказы, гонки порядка,
повторные доставки. Два писателя в один процесс — это уже не журнал, а
проблема консенсуса; ответить на неё значит построить другую систему
(Paxos/Raft/CRDT-слияние событий), в которой ни одно из наших свойств —
ни I1, ни воспроизводимость, ни «машина оператора — единственный узел
доверия» — не выживает без пересмотра. A2A как протокол делегирования
дополнительно возвращает модель в маршрутизацию: агент решает, какому
агенту делегировать, — это прямое нарушение I1 на уровне выше шага.

**Что закрывает потребность.** Федеративный export/import журнала
(волна I): переносимая, проверяемая история прогона между машинами без
разделения записи.

**Условие пересмотра.** Формальная модель слияния журналов с
детерминированным разрешением конфликтов и доказанным сохранением
replay-семантики. До неё — нет.

## L2. WASM-снапшоты QuickJS — отклонено

**Тезис.** Снапшотить нечего, а главное — незачем.

**Доказательство.** Технически: куча JS несериализуема — замыкания,
хост-объекты, незавершённые промисы не переживают сериализацию; QuickJS
не имеет snapshot API уровня V8, а портировать его — проект размером с
сам QuickJS. Экономически: программы CodeAct короткоживущие (секунды),
стоимость снапшота и его восстановления выше стоимости повторного
исполнения. Семантически: восстановление после сбоя уже решено журналом —
resume начинает шаг заново, детерминированно; снапшот середины
JS-исполнения добавляет вторую, несогласованную с журналом точку
восстановления — две истины о состоянии, что недопустимо.

**Условие пересмотра.** Появление долгоживущих интерактивных
CodeAct-программ (часовой порядок) И upstream-снапшоты в QuickJS.
Одного без другого недостаточно.

## L3. Спекулятивные ветки CodeAct — отклонено

**Тезис.** Спекуляция исполняет то, что код решил не исполнять.

**Доказательство.** Ветка выбирается детерминированным кодом по значению
контракта — мгновенно; спекулятивный прогон альтернативных веток ничего
не ускоряет, потому что нечего ускорять. Цена же реальная: спекуляция —
это исполнение программ, написанных моделью, для веток, которые будут
отброшены: расход токенов, вызовы инструментов (пусть и в песочнице) с
наблюдаемыми побочными эффектами, и события отброшенного исполнения в
журнале — после чего replay обязан отвечать на вопрос «что было
спекуляцией», загрязняя семантику журнала. Получаем маргинальную ценность
при цене в основание наблюдаемости.

**Условие пересмотра.** Ветки с тяжёлым вычислением условия (минуты) —
тогда спекуляция обретает объект ускорения. Таких веток в дизайне нет
по определению: условие — чтение значения из состояния.

## L4. Кэш ответов по похожести эмбеддингов — отклонено (кэш по точному хэшу поставлен, 0.42.0)

**Тезис.** «Похоже» — не «равно», а кэш обязан возвращать «равно».

**Доказательство.** Точный кэш детерминирован: одинаковый ключ — тот же
ответ, байт в байт, доказуемо. Similarity-кэш заменяет равенство порогом
близости эмбеддингов: два различных запроса получают один ответ, и граница
«достаточно похоже» непроверяема кодом — то есть контракт формы пройден,
а смысл подменён молча. Эксплуатационно: попадание similarity-кэша без
журналирования искажает учёт стоимости (волна A), а с журналированием
требует на каждое попадание объяснимости («почему этот ответ»), которой
порог косинуса не даёт. Отладка прогона превращается в гадание: вчера
ответ был иной при том же входе — и это не воспроизвести.

**Что закрывает потребность.** Exact-hash кэш (`response_cache`, 0.42.0):
90% экономии при 0% двусмысленности.

**Условие пересмотра.** Opt-in флаг на процесс + журналирование скора
попадания + human_gate на низких скорах. Даже тогда — не дефолт.

## Общий принцип

Все четыре отказа — один аргумент в четырёх обличьях: предложение
переносит решение или состояние из детерминированного кода в
недетерминированную область (сеть, куча JS, спекуляцию, близость
векторов). berimor стоит на обратном. Пересмотр возможен только через
формализацию, возвращающую детерминизм, — не через демонстрацию, что
«вроде работает».
