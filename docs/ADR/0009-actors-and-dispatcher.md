# ADR-0009: Акторы и диспетчер вместо оркестратора-модели для мультиагентности

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Нужна мультиагентность — несколько независимых процессов, коммуникация между ними — без пересоздания рисков координации моделью (см. ADR-0004).

## Решение

Актор = процессная модель + своя память (профиль типа `actor`, см. ADR-0013) + почтовый ящик. Коммуникация — подписанные конверты через шину событий; общей памяти между акторами нет. Диспетчер назначает задачи акторам по декларативным правилам в коде; после заданного числа неудач задача блокируется и уходит человеку.

## Альтернативы

- **Общее разделяемое состояние между акторами вместо конвертов** — отклонено: открывает гонки записи и класс дефектов «чтение чужих черновиков»; несовместимо с правилом «один писатель состояния на инстанс процесса».

## Последствия

Больше сообщений в системе (конверты вместо прямого доступа к чужому состоянию), но полностью устранён целый класс гонок конкурентного доступа между независимыми акторами.
