# ADR-0016: Консистентность графа сущностей — entity resolution и типизированные контракты

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Опциональный граф сущностей в модели памяти называл «построение графа из неструктурированного текста с сохранением согласованности типов» главной сложностью, но не специфицировал механизм разрешения дубликатов сущностей и согласованности типов узлов/рёбер.

## Решение

**Entity resolution:** кандидат на новый узел проверяется на совпадение с существующим сначала по точному идентификатору домена (если тип сущности его объявляет), иначе по явной таблице псевдонимов (`alias_of` — типизированное ребро, создаваемое через контракт). Близкое совпадение по эмбеддингу — только предложение кандидата, не автослияние: ниже порога точного совпадения решение уходит человеку тем же конфликт-событием, что и при консолидации фактов. **Согласованность типов:** каждый тип узла и ребра — версионируемый контракт Mediation, объявляющий обязательные поля и допустимые пары связей; несоответствие — отказ, новый тип — событие + подтверждение (I2). **Конфликтующие рёбра** — конфликт-событие, не молчаливая перезапись.

## Альтернативы

- **Автослияние по порогу близости эмбеддинга без требования точного идентификатора** — отклонено: риск слияния двух разных сущностей с похожими текстовыми описаниями (галлюцинированная связь), которую потом трудно отличить от настоящего совпадения задним числом.

## Последствия

Меньше автоматизации на entity resolution в сложных случаях (больше конфликт-событий к человеку), но исключён класс ошибок «тихое слияние двух разных сущностей».
