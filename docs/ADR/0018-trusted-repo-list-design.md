# ADR-0018: Доверенный список — доверие к репозиторию не равно доверию к артефакту вслепую

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Нужен механизм ограничения источников плагинов и обновлений — но без обязательного централизованного удостоверяющего центра, что нарушило бы I5 (минимум внешних зависимостей).

## Решение

Локальный журналируемый список записей (`repo`, `allowed_ref`, `signer_identity`, `capability_ceiling`, происхождение записи). Доверие к репозиторию разрешает не запрашивать подтверждение человека на каждый отдельный релиз — но каждый скачанный артефакт всё равно верифицируется криптографически по закреплённому `signer_identity`; список определяет, для кого выполняется проверка, а не заменяет саму проверку. Изменение списка — событие и подтверждение человека (I2), а не автоматический сетевой эффект.

## Альтернативы

- **Централизованный корневой ключ или удостоверяющий центр для подписи всего списка** — отклонено: добавляет обязательную внешнюю зависимость (нарушение I5) и единую точку отказа/компрометации для всех установок сразу.

## Последствия

Корень доверия — человек-администратор конкретной установки, а не внешний орган: проще эксплуатировать локально и не требует внешней инфраструктуры, но нет автоматической федерации доверия между разными установками системы.
