# ADR-0022: Wasmtime + WASM для структурной изоляции CodeAct

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

I6 требует, чтобы деструктивное блокировалось кодом до выполнения, и явно предпочитает структурные гарантии спискам запретов, которые устаревают быстрее, чем их успевают обновлять.

## Решение

Программа CodeAct компилируется в WASM и исполняется в Wasmtime. Основной язык генерации — ограниченное подмножество JS (шире представлено в обучающих данных моделей, чем полноценный Python-в-WASM, при меньшей стоимости холодного старта). Два независимых барьера: статическая проверка исходника (белый список идентификаторов, запрет `eval`/динамического импорта/сетевых глобальных объектов) — до компиляции; отсутствие ambient-доступа к ОС/сети внутри WASM linear memory — структурно, после компиляции. Лимиты — метрика «топлива» Wasmtime (детерминированный лимит по числу инструкций, а не недетерминированный wall-clock таймаут).

## Альтернативы

- **Песочница на уровне ОС-процесса (seccomp/контейнер)** — отклонено как основной путь: платформенно-специфична, требует разных механизмов под разные ОС из деплой-матрицы (`deployment.md`), тогда как гарантия WASM одинакова на всех целевых платформах.
- **Python-в-WASM (Pyodide-подобная сборка) как основной путь** — отклонено: тяжелее по времени холодного старта и размеру артефакта; оставлено как конфигурируемый профиль для доменов с тяжёлыми числовыми вычислениями, где выигрыш в качестве генерации у моделей перевешивает стоимость старта.

## Последствия

Модель ограничена подмножеством JS вместо «любого языка, который знает» — сужает пространство генерации в обмен на единую, кросс-платформенную, структурную (не списковую) гарантию изоляции.
