# ADR-0013: Память актора — профиль на той же оси изоляции, что и арендатор

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Главный документ описывал «свою память» актора отдельно от механизма профилей/арендаторов в спецификации памяти — два параллельных, нигде явно не связанных механизма изоляции. Найдено при ревью архитектуры.

## Решение

Память актора — профиль типа `actor`, та же ось изоляции, что и у профилей пользователей/арендаторов; те же правила маршрутизатора («межпрофильное чтение — только явным правилом») применяются к акторам без отдельного механизма. Семантический и процедурный слои по умолчанию остаются общими на уровне арендатора, а не приватны актору, если процесс явно не объявит иное.

## Альтернативы

- **Отдельный, не связанный с профилями механизм изоляции памяти акторов** — отклонено: удваивает поверхность реализации и проверки правил изоляции без выигрыша в выразительности — то же самое свойство («межпрофильное чтение только по правилу») пришлось бы поддерживать в двух местах.

## Последствия

Один код-путь проверки изоляции покрывает и акторов, и пользователей/арендаторов; цена — процесс, которому реально нужна приватная семантическая память своего актора, должен явно объявить это в конфигурации, а не получить её по умолчанию.
