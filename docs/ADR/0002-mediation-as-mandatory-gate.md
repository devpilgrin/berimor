# ADR-0002: Mediation как обязательный шлюз между выводом модели и состоянием

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Вывод модели может быть невалидным по форме, содержать лишние поля (в том числе спровоцированные внедрённой инструкцией) или прямо противоречить состоянию системы. Инвариант I3 требует, чтобы ни один вывод модели не становился состоянием без валидации.

## Решение

Единая точка между любым выводом модели и состоянием/инструментом/пользователем: `parse → schema → policy → commit`, с повторами (до 2) при ошибках разбора/схемы и детерминированной эскалацией при нарушении политики. Схема запрещает поля сверх контракта — закрытая схема как защита от инъекции лишних «служебных» полей.

## Альтернативы

- **Валидация по месту в каждом шаге отдельно** — отклонено: дублирование логики, риск, что новый тип шага «забудет» вставить проверку.
- **«Мягкая» валидация с автоисправлением невалидного вывода той же моделью** — отклонено: увеличивает зависимость от модели ровно там, где нужна детерминированность; исправление — это ещё один непроверенный вывод той же ненадёжной стороны.

## Последствия

Каждый отказ становится событием — телеметрия для оценки деградации модели/процесса получается как побочный эффект архитектуры контроля, а не как отдельная система, которую нужно строить и поддерживать independently.
