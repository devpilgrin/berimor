# ADR-0011: Выбор провайдера и управление стоимостью/латентностью — детерминированное правило

**Статус:** Принято
**Дата:** 2026-07-29

## Контекст

Внутри одного класса способностей может быть несколько провайдеров (локальный инференс + несколько удалённых) с разной стоимостью и латентностью. Нужен способ выбора между ними, не оставляющий решение модели и не создающий непредсказуемого поведения при сбое одного из провайдеров.

## Решение

Селектор — код: предпочтение локального инференса при равном классе (нулевая предельная стоимость, данные не покидают периметр) → наименьшая стоимость среди удалённых провайдеров в пределах латентность-бюджета шага → явный фиксированный порядок предпочтения в конфигурации. `cost_budget` и `latency_budget` — опциональные детерминированные прерыватели процесса, наравне с `token_budget`/`max_steps`/`timeout`. Порядок переключения на резервного провайдера при деградации — заранее заданная конфигурация на класс, определённая до инцидента, а не решение, принимаемое в момент сбоя.

## Альтернативы

- **«Модель сама решает, какого провайдера использовать»** — отклонено: прямое нарушение I1.
- **Переключение на первого попавшегося доступного провайдера без заранее заданного порядка** — отклонено: непредсказуемое поведение под нагрузкой и при частичной деградации пула, невозможно протестировать заранее контрактным тестом.

## Последствия

Требует явно конфигурировать порядок провайдеров на каждый класс заранее — дополнительная эксплуатационная нагрузка на этапе настройки, взамен на предсказуемое, воспроизводимое поведение при деградации любого отдельного провайдера.
