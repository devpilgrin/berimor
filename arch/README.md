# arch — архитектура идеальной агентной системы

Самодостаточные проектные документы. Не ссылаются на внешние проекты, продукты и источники: каждое заимствованное решение описано по сути, а не по имени.

## Содержание

- `ideal-agent-architecture.md` — главный документ: философия, 8 инвариантов, карта компонентов, жизненный цикл задачи, разделение «код решает / модель исполняет», этапы внедрения.

### Спецификации компонентов

- `process-engine.md` — детерминированный остов: модель процесса (10 типов шагов), иммутабельное состояние, восстановление из журнала, шаг человеческого контроля, тестирование.
- `mediation.md` — медиационный слой: контракты, 4 стадии (parse → schema → policy → commit), повторы и эскалация, телеметрия отказов.
- `executors.md` — исполнители шагов: ToolOnly, StructuredLLM, CodeAct (изолированная среда, статическая проверка программы, допуск по классам моделей), AgentStep.
- `memory-model.md` — слои памяти: рабочая, эпизодическая, семантическая, процедурная; правила записи и чтения; защита от отравления; изоляция профилей.
- `security-model.md` — модель угроз, 9 слоёв защиты (L0–L8), режимы подтверждений, мультиагентная безопасность, аудит.
- `deployment.md` — развёртывание и обновление через npm + GitHub: определение платформы, доверенный список репозиториев, само-обновление и установка плагинов как процессы, пайплайн сборки и тестирования, модель угроз дистрибуции.
- `stack.md` — обоснованный выбор конкретных технологий под архитектуру: ядро на Rust, SQLite как единое встраиваемое хранилище (события/полнотекст/векторы/граф), Wasmtime для CodeAct, MCP как протокол инструментов, npm-bootstrap. С разбором отклонённых альтернатив.

Два последних документа — единственные в разделе, называющие конкретные технологии; раздача и её стек неотделимы от конкретного реестра, хостинга релизов и рантайма.

## Диаграммы и представления (views)

Системная, компонентная, данных, сетевая архитектуры — и ещё семь представлений (runtime, состояния, безопасность как картинка, качественные атрибуты, словарь понятий, реестр рисков) — оформлены отдельно в `views/`, диаграммами поверх текста этих документов. См. `views/README.md`.

## Журнал решений

Каждое решение, зафиксированное в документах выше (включая отклонённые альтернативы и причины), оформлено отдельной записью в `../ADR/` — см. `../ADR/README.md` для полного списка.

## Принцип чистоты документов

Документы не упоминают конкретные языки, фреймворки, продукты и статьи. Если решение заимствовано извне, в тексте описана суть решения (принцип, механизм, обоснование), а не дана отсылка. Связь архитектуры с исследовательской базой поддерживается вне этих документов.
