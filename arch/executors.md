# Executors — спецификация исполнителей шагов

> Спецификация компонента. См. `ideal-agent-architecture.md` §3.3. Самодостаточна.

## 1. Три исполнителя

| Исполнитель | Зона применения | Модель | Изоляция |
|-------------|-----------------|--------|----------|
| **ToolOnly** | шаг без семантики: чтение/запись/вызов внешней системы | нет | capability-гейты |
| **StructuredLLM** | извлечь, классифицировать, суммаризировать, перевести | да, узко | контракт Mediation |
| **CodeAct** | вычисления, итерации по данным, композиция вызовов | да | изолированная среда + Mediation результата |

Выбор исполнителя — свойство шага процессной модели (задаётся кодом процесса), не решение модели.

## 2. ToolOnly

- Один вызов инструмента; аргументы — шаблон из состояния, резолвятся движком.
- Перед вызовом — capability-слой: статический запрет, сетевой гейт, подтверждение по политике инструмента.
- Результат записывается в состояние как есть: инструмент — доверенный код, контракт не нужен, но событие фиксируется.
- Принцип: если шаг не требует понимания текста — модели в нём нет вообще. Дешевле, быстрее, предсказуемо.

## 3. StructuredLLM

- Подсказка собирается движком: роль шага + схема контракта + пример из той же версии + срез состояния (отобранный кодом-маршрутизатором).
- Ответ проходит Mediation: разбор → схема → политика → commit.
- **Допуск по классам моделей:** любой класс, включая слабые локальные — задача шага узкая, контракт ловит ошибки формы.
- Анти-паттерн: «пусть модель сама решит, какой инструмент вызвать» — это территория свободного режима, не структурированного шага.

## 4. CodeAct

### 4.1. Почему программа, а не одиночные вызовы инструментов

Три независимых наблюдения:

- **Качество:** действия в форме программы превосходят по успешности цепочки одиночных вызовов — программа выражает циклы, условия и композицию, которые в формате «один вызов за раз» требуют многих обращений к модели с накоплением ошибок.
- **Паритет слабых моделей:** именно в режиме генерации кода модели с открытыми весами догоняют проприетарные — писать код им проще, чем эмитировать строгие структурированные вызовы. Для системы с локальным инференсом это режим паритета.
- **Стоимость:** одна программа вместо пяти обращений к модели — меньше токенов и меньше круговых задержек.

### 4.2. Цикл

```
срез состояния + сигнатуры инструментов (как стабы) → модель
  → программа (статическая проверка: белый список импортов и имён)
  → изолированное выполнение (лимиты: время, память, число вызовов)
  → {логи, результат} → Mediation (результат по контракту шага)
  → commit | повтор | эскалация
```

- **Инструменты внутри программы** — функции-стабы, маршалящие в реальный рантайм инструментов через межпроцессный вызов; capability-гейты действуют на каждый вызов: сгенерированный код не обходит статические запреты и подтверждения.
- **Статическая проверка до запуска:** разрешены только стандартная библиотека без доступа к ОС и явно одобренные библиотеки обработки данных; запрещены динамическое выполнение строк, динамический импорт, прямые сетевые вызовы вне стабов.
- **Единственный выход** — функция финального ответа; её аргумент валидируется контрактом шага.
- Лимиты времени, памяти и числа вызовов инструментов — детерминированные прерыватели.

### 4.3. Допуск по классам моделей

| Класс модели | Допуск |
|--------------|--------|
| сильный (внешние провайдеры) | полный CodeAct |
| средний | CodeAct с уменьшенным лимитом и обязательным примером в подсказке |
| слабый (локальные малые) | только StructuredLLM; CodeAct — с явным разрешением в процессе |

Допуск — правило в коде, а не «модель решила попробовать».

## 5. AgentStep (свободный цикл — выделенный случай)

- Исполнитель для шага типа `agent_step` и пользовательского люка в свободный режим.
- Цикл «рассуждение → действие → наблюдение» с опциональными стратегиями: самокритика (модель оценивает свой шаг до продолжения) и «предложи — выполни — проверь» (отдельный вердикт по критериям после выполнения).
- Жёсткая рамка: максимум ходов, бюджет токенов, снапшот перед каждой правкой, подтверждения инструментов; результат — через Mediation в состояние процесса (если вызван из процесса) или пользователю (если люк).
- **Не используется для шагов, выразимых процессной моделью.** Контур здоровья навыков отслеживает злоупотребление `agent_step`: если шаг стабильно решается процессом, свободный режим заменяется процессным.

## 6. Таблица выбора при проектировании процесса

| Задача шага | Исполнитель |
|-------------|-------------|
| Получить запись из внешней системы | ToolOnly |
| «Извлеки из письма номер заказа и тональность» | StructuredLLM |
| «Смержи 12 таблиц, посчитай агрегаты, найди аномалии» | CodeAct |
| «Разберись, почему падает тест, и почини» | AgentStep (или люк) |
| «Определи риск и реши, куда дальше» | StructuredLLM (оценка риска) + branch (решение — код) |

## 7. Границы

- Исполнитель не выбирает себя сам и не меняет тип шага.
- Исполнитель не пишет в состояние напрямую — только через Mediation.
- Исполнитель не обходит capability-слой: все его вызовы инструментов проходят те же гейты, что и прямые.
