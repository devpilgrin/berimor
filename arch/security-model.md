# Security Model — спецификация модели безопасности

> Спецификация компонента. См. `ideal-agent-architecture.md` §3.7. Самодостаточна.

## 1. Модель угроз

| Угроза | Механизм атаки/сбоя | Слой защиты |
|--------|---------------------|-------------|
| Деструктивная команда | модель или внедрённая инструкция генерирует разрушительную операцию | безусловный статический запрет до выполнения |
| Выход за рабочую область | обход через абсолютные пути, симлинки, цепочки команд, несколько целей одной операции | jail + разрешение путей + анализ всех целей |
| Подделка запроса к внутренним сервисам (SSRF) | модель вызывает внутренний адрес по наводке из контекста | сетевой гейт: приватные цели — через подтверждение |
| Утечка секретов | секрет попадает в контекст, логи, плагины, тексты подтверждений | маскировщик на всех границах; модель видит только алиасы |
| Внедрение инструкций (prompt injection) | вредоносный текст в данных инструмента или документе | закрытые контракты, аргументы только из валидированных объектов, изоляция инструкций от данных |
| Отравление памяти | запись вредоносного факта, который позже выдаётся всем задачам | дедупликация, обязательный источник, пониженный вес ненадёжных источников |
| Имперсонация компонента | плагин публикует события под чужим топиком или читает чужие секреты | ACL манифеста, ограниченные доступы |
| Эмерджентные циклы координации | агенты вызывают друг друга бесконечно, взаимные блокировки, противоречивые решения | лимиты движка, диспетчер-правила, аварийная заморозка |
| Тихая деградация модели | обновление провайдера ухудшило ответы, никто не заметил | доля отказов валидации как постоянная метрика |
| Молчаливая мутация системы | агент «улучшает» навык или конфигурацию без ведома | контур здоровья: событие + подтверждение |

## 2. Слои защиты (эшелонированная оборона)

```
Вход (поверхность)
  │  L0: аутентификация канала, ограничение частоты
  ▼
Планирование
  │  L1: маршрутизатор — только известные классы задач; неизвестное → человек
  ▼
Исполнение шага
  │  L2: Mediation — контракт + политика + контроль утечек
  │  L3: Capability — запрет до выполнения, jail, сетевой гейт, подтверждения
  │  L4: Изолированная среда — сгенерированный код в отдельном процессе,
  │      статическая проверка программы, лимиты ресурсов
  ▼
Данные
  │  L5: Маскировщик — аргументы/вывод инструментов, мост к хранилищу,
  │      тексты подтверждений, запись в память
  │  L6: Дедупликация и источники — защита памяти от отравления
  ▼
Изменение системы
  │  L7: Контур здоровья навыков — любая мутация через событие + подтверждение
  ▼
Наблюдение
  L8: журнал событий + трассировка + воспроизведение;
      события безопасности — первоклассные
```

## 3. Режимы подтверждений

| Режим | Семантика | Применение |
|-------|-----------|------------|
| `deny` | безусловная блокировка кодом; подтверждение не отменяет | запретные классы операций, нарушение jail, попытка утечки |
| `smart` | детерминированные правила риска: чтение свободно, мутации — подтверждение; правила — код, не модель | интерактивный режим по умолчанию |
| `manual` | подтверждение на всё, кроме явно read-only | параноидальный профиль |
| `off` | без подтверждений | только изолированные профили; явное включение владельцем |

Принципы:

- **Расширение прав — opt-in, сужение — никогда молчаливое.** Усиление безопасности по выбору владельца (изолированная среда, аппаратные ключи), а не трение для всех пользователей.
- **Деструктивные действия над внешними системами** (базы данных, API, деплои) — всегда подтверждение, независимо от режима: снапшоты покрывают только локальные файлы, внешние системы откатить нельзя.
- **Пароли и пин-коды без навязанных правил сложности** — владелец выбирает удобный уровень; усиление защиты предлагается, но не требуется.

## 4. Мультиагентная безопасность

- **Конверты акторов подписаны отправителем;** шина проверяет ACL топика: компонент не может публиковать события под чужим именем. Источник ACL — статический манифест на диске, который сам компонент переопределить не может.
- **Общей памяти нет:** акторы общаются конвертами, а не разделяемым состоянием; у состояния процесса — один писатель. Это устраняет гонки и целый класс «чтения чужих черновиков».
- **Аварийная заморозка** всех акторов за ограниченное время (цель — доля секунды); активные задачи не теряются, а ставятся обратно в очередь.
- **Межкомпонентные контракты:** выход актора A, становящийся входом актора B, проходит Mediation — внедрение инструкций «агент в агента» ловится той же закрытой схемой.

## 5. Аудит и соответствие требованиям

- **Журнал событий = аудит-трейл:** кто, что, когда, с каким контрактом, по какому подтверждению. Этого достаточно для требований прослеживаемости и человеческого надзора, которые регуляторы предъявляют к высокорисковым ИИ-системам.
- **Воспроизведение:** любой инцидент воспроизводится без моделей свёрткой событий — расследование не зависит от доступности провайдера.
- **Отчётность:** события безопасности агрегируются (срабатывания запретов, попытки утечек, блокировки сетевого гейта) — вход для периодического ревью политики человеком, не для автоподстройки (I2).

## 6. Принципиальные «нет»

- **Нет проверки «модель судит модель».** Слабому звену нельзя доверять проверку сильного; сильное звено делает каждый шаг зависимым от внешнего провайдера и удваивает стоимость. Валидация — только контрактом и кодом.
- **Нет этического модуля.** Отказы кодируются явно: запретные таблицы, политики, тесты. Поведение объяснимо, воспроизводимо, проверяемо.
- **Нет неявного расширения привилегий:** новый инструмент, топик, секрет — манифест и подтверждение.
- **Нет секретов вне хранилища секретов:** ни в памяти, ни в подсказках, ни в конвертах, ни в логах — везде алиасы и маскировка.
