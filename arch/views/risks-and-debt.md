# Risks and Technical Debt — реестр рисков и осознанных компромиссов

> arc42 §11. Разделяет то, что уже принято как компромисс с понятной ценой, от того, что реально ещё не решено и требует дальнейшей работы.

## 1. Принятые компромиссы (accepted trade-offs)

| Компромисс | Цена | Почему принято | ADR |
|---|---|---|---|
| CodeAct ограничен подмножеством JS, не полным Python | Хуже эргономика для моделей, тренированных преимущественно на Python | Меньше холодный старт песочницы; JS-подмножество перекрывает большинство задач композиции инструментов | ADR-0022 |
| Корень доверия для плагинов/обновлений — локальный человек-администратор, не централизованный CA | Нет автоматической федерации доверия между установками одной организации | Централизованный CA нарушил бы I5 (обязательная внешняя зависимость) | ADR-0018 |
| Семантическая проверка (смысл вывода) не выполняется второй моделью | Редкие смысловые ошибки не ловятся автоматически, только оценочным циклом и риск-ветками | LLM-as-judge удваивает стоимость и делает каждый шаг зависимым от внешнего провайдера | ADR-0004 |
| Rust как язык ядра | Выше порог входа, медленнее первая итерация разработки | Компилятор механически отклоняет классы ошибок, которые архитектура объявила недопустимыми (I1, I3, I6, I7) | ADR-0020 |
| Все данные в одном файле SQLite | Ограничение на очень высокую конкурентную запись | Смягчено правилом «один писатель на инстанс процесса», действующим независимо от выбора БД | ADR-0021 |

## 2. Открытые риски (требуют дальнейшей работы)

| Риск | Описание | Статус | Предлагаемое направление |
|---|---|---|---|
| Корреляция офлайн-/онлайн-качества не подтверждена измерением | `ideal-agent-architecture.md` §3.11 называет это «проверяемой гипотезой», но методология самого измерения не описана | Открыто | Спроектировать план измерения корреляции как отдельную задачу до масштабного использования офлайн-оценки для решений о допуске моделей |
| Плотность одновременных `human_gate` при масштабировании числа арендаторов | Лимит очереди (ADR-0015) описан на уровне правила, но не откалиброван численно | Открыто | Нагрузочное моделирование диспетчера на реалистичном профиле эскалаций |
| Качество локальных эмбеддингов (llama.cpp) против удалённых | Не бенчмаркано в текущей документации | Открыто | Сравнительный замер точности гибридного поиска (`memory-model.md`) на золотом наборе фактов |
| Рост графа сущностей при большом числе профилей/арендаторов | Рекурсивные CTE в SQLite для обхода графа — производительность на больших графах не оценена | Открыто | Нагрузочный тест на графе реалистичного размера; при необходимости — партиционирование по профилю |
| Одна CI-платформа (GitHub Actions) как единая точка для keyless-подписи | Компрометация самой CI-платформы обесценивает гарантию provenance | Принято как риск уровня инфраструктуры, не архитектуры | Мониторинг статуса безопасности платформы; вне периметра проектных решений |

## 2. Формат записи

Каждый новый риск или компромисс — новая строка с датой обнаружения в комментарии коммита; при разрешении риска — перенос в раздел 1 с ссылкой на ADR, фиксирующий решение, а не удаление строки.
