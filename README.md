# Berimor

База знаний и архитектурный проект по агентным системам: от исследовательских источников до исполняемой архитектуры и её реализации.

## Структура

| Слой | Директория | Содержимое |
|---|---|---|
| Источники | `docs/rnd/` | собранные данные: источники, фреймворки, разборы, анализ паттернов. См. `docs/rnd/README.md` |
| Архитектура | `docs/arch/` | самодостаточная архитектура идеальной агентной системы — принципы, компоненты, диаграммы (`docs/arch/views/`). См. `docs/arch/README.md` |
| Решения | `docs/ADR/` | журнал архитектурных решений: контекст, альтернативы, последствия. См. `docs/ADR/README.md` |
| План разработки | `docs/ROADMAP.md` | очередь задач по фазам, декомпозиция на подзадачи, сложность, класс модели-исполнителя |
| Код (скелет) | `crates/` | Rust-workspace ядра — по одному крейту на компонент архитектуры |
| Bootstrap | `bootstrap/` | npm-пакет установщика/обновления (TypeScript) |
| Тестовые данные | `fixtures/golden/` | золотые наборы: примеры процессов, контрактов, вредоносных вводов |

## Принцип работы

`rnd` — слой фактов и источников. `arch` — слой чистых решений: не упоминает конкретные проекты и продукты (кроме `docs/arch/deployment.md` и `docs/arch/stack.md`, где это осознанное исключение), а излагает архитектуру так, чтобы её можно было реализовать на любом стеке. `docs/ADR/` фиксирует, почему принято каждое решение, включая отклонённые альтернативы. `docs/ROADMAP.md` превращает архитектуру в очередь задач. `crates/` и `bootstrap/` — код, начатый по этой очереди.

## Статус

Архитектурная стадия завершена (принципы, диаграммы, решения, план). Реализация — на стадии скелета: крейты компилируются, интерфейсы между ними зафиксированы, тела реализаций — по `docs/ROADMAP.md`.
